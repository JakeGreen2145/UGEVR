# UI capture and interaction in shipped Unity players

Research date: 2026-10-13. This answers [Which Unity UI capture and interaction mechanisms remain usable in shipped players?](https://github.com/JakeGreen2145/UGEVR/issues/22) and extends the UI section of the [pipeline report](https://github.com/JakeGreen2145/UGEVR/blob/2820e8c0fee497fe933f00a9fe48feae28fb570c/docs/research/unity-render-pipelines.md). It supplies facts for the human's UI decision. It selects no architecture and includes no gameplay, build, installation or runtime-setting changes.

## Answer and evidence boundary

There are public mechanisms for redirecting and interacting with several common Unity UI systems. They differ enough that one camera texture and one synthetic click cannot establish general support. Screen Space Overlay uGUI renders separately from scene cameras. UI Toolkit has an explicit panel target texture in the inspected 2022.3 source. IMGUI executes event-driven callbacks with engine-owned layout and control state. Custom UI needs identification of its actual rendering and input contract. These facts support separate, capability-probed adapters rather than a universal capture assumption. [Canvas modes, 2022.3](https://docs.unity3d.com/2022.3/Documentation/Manual/class-Canvas.html), [PanelSettings source](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/GameObjects/PanelSettings.cs), [OnGUI, 2022.3](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/MonoBehaviour.OnGUI.html)

No route in this report is validated inside Firewatch or Outer Wilds. Their simulated stereo runs establish neither game UI capture nor widget interaction. A clickable injector-owned menu proves its own event route only. Final desktop-frame capture may provide a usable opaque image but does not prove isolated transparent UI, stereo world UI, or native widget hit testing. Those are separate claims with separate probes.

## Source versions

- UnityCsReference `2022.3.0f1`, commit `91471827ee2cab002d877b827d67d120c09ba9d5`, supplies Canvas bindings, UI Toolkit runtime panel implementation and IMGUI wrappers. These include native calls, not the full native engine. [Pinned source tree](https://github.com/Unity-Technologies/UnityCsReference/tree/91471827ee2cab002d877b827d67d120c09ba9d5)
- uGUI tag `2017.4.16f1`, commit `7af367ae08eae554894fa453939b2b58b87d52d7`, supplies a version-qualified older EventSystem and raycaster implementation. It is relevant to the older Mono cohort but is not the exact Firewatch `2017.4.40f1` implementation. [Pinned uGUI tree](https://github.com/Unity-Technologies/uGUI/tree/7af367ae08eae554894fa453939b2b58b87d52d7)
- Input System commit `e29989176f3a8473ba30854e4bfae953083eba28` declares version `1.7.0`, minimum Unity `2019.4`. It supplies UI input and tracked raycaster code. Minimum editor version does not establish presence in every player of that version. [Package manifest](https://github.com/Unity-Technologies/InputSystem/blob/e29989176f3a8473ba30854e4bfae953083eba28/Packages/com.unity.inputsystem/package.json)
- A separate uGUI snapshot on the `6000.0` branch, commit `58c0ead281dc1cf042e8831606850413524971bb`, declares package `2.0.0`. Its manifest's `unity` field says `2019.2`; this is not proof that all its code works in 2019.2 players. It supplies a concrete later API comparison. [Package manifest](https://github.com/Unity-Technologies/uGUI/blob/58c0ead281dc1cf042e8831606850413524971bb/com.unity.ugui/package.json)

Official manual URLs specify release families but can change editorially. Immutable source links identify the inspected code. No 2022.3 UI Toolkit claim here is projected back to Unity 2017.4 or 2019.4.

## Capture mechanisms

| UI family | Retained stock mechanism or candidate | Constraints to test in the actual player |
| --- | --- | --- |
| uGUI Screen Space Overlay | Candidate conversion to Screen Space Camera using a dedicated capture camera and its RenderTexture; alternatively intercept the original separate UI rendering. | Overlay has no public Canvas targetTexture in the inspected bindings. Changing mode/camera can change sizing, sorting, masks, event camera and game assumptions. Conversion is a candidate, not a verified equivalence. |
| uGUI Screen Space Camera | Capture or redirect the assigned camera through the pipeline's supported target path. | The assigned camera can also draw scene content. Camera stack membership, plane distance, other canvases, masks and draw order can prevent clean isolation. |
| uGUI World Space | Original stereo scene rendering can retain geometry, depth and occlusion. Separate texture capture is an optional reconstruction. | Flattening changes spatial behavior. Interaction requires the corresponding ray/camera and occlusion rules. Original camera capture does not establish controller ray interaction. |
| UI Toolkit runtime panels, inspected 2022.3 | `PanelSettings.targetTexture`, with panel size/scale, clear settings and coordinate mapping. | PanelSettings is shared by its UIDocuments. Redirecting it affects the whole panel. Capture must preserve order, display identity, focus and existing game-owned targets. |
| IMGUI OnGUI | Candidate interception during original GUI rendering, or a game adapter that owns its draw path. | No equivalent public runtime PanelSettings target API was established here. Reinvoking arbitrary OnGUI methods is not a safe general capture method. |
| Custom render-to-texture UI | Observe an existing RenderTexture and its actual producer, then copy or share it under the GPU ownership contract. | Identification, lifetime, readiness, texture cropping, UV transforms, transparency and input semantics remain game-specific. Some custom UI is ordinary geometry or native rendering instead. |
| Final desktop image | Copy the completed displayed frame at the correct graphics stage. | It contains scene/UI composition and may be opaque. Removing the scene by color subtraction or assuming back-buffer alpha isolates UI is unproven. It does not identify clickable objects. |

The Canvas rows follow the [2017.4 Canvas manual](https://docs.unity3d.com/2017.4/Documentation/Manual/class-Canvas.html), the [2022.3 Canvas manual](https://docs.unity3d.com/2022.3/Documentation/Manual/class-Canvas.html) and [2022.3 Canvas bindings](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/Modules/UI/ScriptBindings/UICanvas.bindings.cs). The bindings expose renderMode, worldCamera, sorting and display fields, not a Canvas target texture. `ForceUpdateCanvases` invokes the render notification callbacks; it is not a public isolated UI draw-to-texture command. Extra calls need callback side-effect checks.

UI Toolkit's 2022.3 panel source sets the active texture and viewport during repaint, then restores the previous camera and target. This establishes a real target path. It does not prove every exception path or injected callback preserves render state. The normal runtime update applies PanelSettings, so changing only a transient internal panel field may be overwritten. [Runtime panel update](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/GameObjects/RuntimePanel.cs), [BaseRuntimePanel repaint](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/Panel.cs#L1195)

Toolkit PanelSettings supports color/depth clearing, display selection, sort order and scaling. A target texture takes precedence over target display. The source recommends `R8G8B8A8_SRGB` for linear project color space and `R8G8B8A8_UNorm` for gamma project color space. This is a version-qualified texture requirement, not permission to assume all custom UI uses the same convention. [2022.3 panel properties](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-Runtime-Panel-Settings.html), [Target texture remarks](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/GameObjects/PanelSettings.cs#L184)

All capture paths need measured alpha and color conventions. A transparent clear does not establish whether shader output and runtime composition agree on straight or premultiplied alpha. RenderTexture sRGB sampling/writing differs with project color space and texture settings. Transparent text edges, masks, gradients, custom materials and a known color/alpha checker must be compared before claiming correct composition. This is an experiment requirement, not a discovered universal blend rule. [RenderTexture.sRGB, 2022.3](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/RenderTexture-sRGB.html)

## Pointer, navigation and focus

### uGUI

The inspected older `GraphicRaycaster` uses PointerEventData screen position, event camera, Canvas mode and display, then checks graphics, masks and blocking geometry. Overlay usually has no event camera. Camera and world UI use a corresponding camera. It rejects mismatched displays when the platform supplies display-relative pointer information. A screen-coordinate adapter therefore needs a display identity as well as x/y. [GraphicRaycaster, 2017.4.16](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/UI/Core/GraphicRaycaster.cs)

`StandaloneInputModule` maintains press target, potential drag, click eligibility and drag state. It sends down, potential-drag initialization, up, eligible click or drop, and end-drag events. It dispatches move/submit/cancel against selection, while `PointerInputModule` handles hover and drag threshold transitions. Calling a Button's callback directly bypasses this protocol and does not prove sliders, scrolling, drag/drop, input fields or focus work. [StandaloneInputModule](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/EventSystem/InputModules/StandaloneInputModule.cs), [PointerInputModule](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/EventSystem/InputModules/PointerInputModule.cs), [EventSystem selection](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/EventSystem/EventSystem.cs)

There is a concrete API difference worth probing. The older snapshot exposes a protected `m_InputOverride` and public input getter; it lacks the later public `inputOverride` setter. Its `BaseInput` has virtual mouse/button/axis methods. The later uGUI 2.0.0 snapshot has a public override property. An injector must inspect the actual module/API; it cannot assume a current setter exists in an old game. Subclass injection, field access, method interception or a new module are candidate mechanisms with backend-specific prerequisites. [Older BaseInputModule](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/EventSystem/InputModules/BaseInputModule.cs), [Older BaseInput](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/EventSystem/InputModules/BaseInput.cs), [Later BaseInputModule](https://github.com/Unity-Technologies/uGUI/blob/58c0ead281dc1cf042e8831606850413524971bb/com.unity.ugui/Runtime/UGUI/EventSystem/InputModules/BaseInputModule.cs)

Input System 1.7's UI module accepts point/click/scroll/navigation actions and tracked device position/orientation. Its tracked raycaster uses world rays and Canvas graphics, with `canvas.worldCamera` required for this implementation. The package guards UI code with `UNITY_INPUT_SYSTEM_ENABLE_UI`. A retained package plus suitable actions/raycaster can support tracked UI; a non-VR game need not have these components configured. Adding them after build is a separate injection experiment. [InputSystemUIInputModule](https://github.com/Unity-Technologies/InputSystem/blob/e29989176f3a8473ba30854e4bfae953083eba28/Packages/com.unity.inputsystem/InputSystem/Plugins/UI/InputSystemUIInputModule.cs), [TrackedDeviceRaycaster](https://github.com/Unity-Technologies/InputSystem/blob/e29989176f3a8473ba30854e4bfae953083eba28/Packages/com.unity.inputsystem/InputSystem/Plugins/UI/TrackedDeviceRaycaster.cs)

### UI Toolkit

The 2022.3 runtime event system orders panels, routes pointer input and updates focused panels. It gives pointer capture priority until release. Public pointer event factories and `visualTree.SendEvent` are available in the inspected source, as are navigation event factories and capture/release extensions. A direct event adapter must reproduce panel selection, hover, pointer identity, pressed-button state and focus behavior that the ordinary dispatcher performs. Sending an event to a picked widget alone omits these obligations. [DefaultEventSystem](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/DefaultEventSystem.cs#L351), [Pointer event factories](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/Events/PointerEvents.cs), [Navigation events](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/Events/NavigationEvents.cs), [Pointer capture API](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/PointerCaptureController.cs)

Unity 2022.3 documents coexistence with uGUI EventSystem and its input modules. Selection and panel focus coordinate through that system. Public `PanelRaycaster` and `PanelEventHandler` are also present in the separately pinned later uGUI package, providing raycast and pointer/navigation conversion rather than a raw button callback. The later implementation is supporting source evidence for that package only. [2022.3 runtime event system](https://docs.unity3d.com/2022.3/Documentation/Manual/UIE-Runtime-Event-System.html), [Later PanelRaycaster](https://github.com/Unity-Technologies/uGUI/blob/58c0ead281dc1cf042e8831606850413524971bb/com.unity.ugui/Runtime/UGUI/EventSystem/UIElements/PanelRaycaster.cs), [Later PanelEventHandler](https://github.com/Unity-Technologies/uGUI/blob/58c0ead281dc1cf042e8831606850413524971bb/com.unity.ugui/Runtime/UGUI/EventSystem/UIElements/PanelEventHandler.cs)

### IMGUI

Unity calls OnGUI for event processing and painting, potentially several times in a frame. The inspected GUIUtility has engine-entry BeginGUI/EndGUI handling, instance layout state, hotControl, keyboardControl and a check that rejects GUI calls outside an active GUI context. A reflective call to an arbitrary OnGUI method does not recreate this context or establish equivalent control IDs. Extra calls can repeat game callback side effects. Native or managed interception during original GUI execution is a candidate, not a proven universal texture/input adapter. [OnGUI, 2022.3](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/MonoBehaviour.OnGUI.html), [GUIUtility implementation](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/Modules/IMGUI/GUIUtility.cs#L177)

Event.mousePosition is writable; Event.Use consumes the GUI event, and GUIUtility exposes capture/focus IDs. These support scoped input interception inside the real GUI lifecycle. They do not suppress unrelated game scripts reading Input or Input System. Consuming one GUI event cannot establish exclusive global input capture. [Event bindings](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/Modules/IMGUI/Event.bindings.cs), [Event.Use, 2022.3](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Event.Use.html), [GUIUtility control state](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/Modules/IMGUI/GUIUtility.cs#L95)

## Coordinates and presentation shapes

The presentation ray must intersect the same surface the user sees. For a flat or curved texture panel, the hit maps to that mesh's UV, then to the captured image rectangle and the original UI coordinate domain. UV tiling, cropping, letterboxing, DPI/panel scale, Y direction and display number must be recorded. A curved panel is a presentation and hit-mapping problem; stock Canvas raycasting does not automatically understand a different curved mesh.

UI Toolkit 2022.3 explicitly supports `SetScreenToPanelSpaceFunction`; its source remarks describe raycasting a textured object and converting `RaycastHit.textureCoord` to texture pixel space. The runtime panel applies its scale after this mapping. `RuntimePanelUtils.ScreenToPanel` and camera-world conversion also exist; the latter flips Y from screen coordinates. uGUI's screen-local helper needs the correct camera, null for overlay, and its boolean result only establishes intersection with the rectangle's plane, not that the point lies inside the rect. [Panel mapping contract](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/GameObjects/PanelSettings.cs#L633), [RuntimePanelUtils](https://github.com/Unity-Technologies/UnityCsReference/blob/91471827ee2cab002d877b827d67d120c09ba9d5/ModuleOverrides/com.unity.ui/Core/GameObjects/RuntimePanelUtils.cs), [ScreenPointToLocalPointInRectangle, 2022.3](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/RectTransformUtility.ScreenPointToLocalPointInRectangle.html)

CanvasScaler can continuously recompute scale using screen/display size in the older inspected code. Changing render mode or texture dimensions therefore needs an explicit layout probe rather than assuming texture pixels equal desktop pixels. [CanvasScaler](https://github.com/Unity-Technologies/uGUI/blob/7af367ae08eae554894fa453939b2b58b87d52d7/UnityEngine.UI/UI/Core/Layout/CanvasScaler.cs)

## Ownership, restoration and shipped-build prerequisites

The following are engineering requirements inferred from the sources, not completed implementation:

- Discover actual UI systems, package versions, root canvases/panels, targets, cameras, event modules and custom components. Track destroyed/recreated objects through backend lifetime-valid handles.
- Save each changed Canvas mode/camera/sorting/display/transform, camera target, panel target/clear/scale and input module/action state. Restore only live objects and injector-owned overrides, accounting for legitimate game changes while active.
- PanelSettings shares one configuration across documents. A temporary clone can change panel identity and focus. Its public screen-to-panel setter does not provide a public getter for an already assigned custom function in the inspected source. Preserve the prior mapping through a validated version adapter or avoid overwriting it. Setting null restores default behavior, not an unknown game mapping.
- Cancel held presses, drags, hover and capture on tracking loss, menu closure, object destruction or disable. Cancellation must avoid generating an unintended click. Restore selection/focus only when its target still exists; restore OS cursor state if changed. Do not disable game navigation indiscriminately or let injected pointer input fire duplicate gameplay actions.
- Keep GPU targets alive until their producer, copies and consumer finish. A game-owned texture is not injector-owned memory. Redirecting/releasing it needs the frame/transport contract and explicit failure cleanup.

Mono permits managed execution only against retained engine/modules and compatible versions. IL2CPP additionally needs callable AOT implementations, metadata, compatible interop and usable generic instantiations; injecting source wrappers does not restore absent machine code. Component subclass/class injection and private member access are separate prerequisites. Managed stripping, missing native UI modules, stripped shaders and absent event implementations have different diagnoses. None proves broad Unity impossibility. [Managed stripping, 2022.3](https://docs.unity3d.com/2022.3/Documentation/Manual/ManagedCodeStripping.html), [IL2CPP build process](https://docs.unity3d.com/2022.3/Documentation/Manual/IL2CPP.html), [Engine access research](https://github.com/JakeGreen2145/UGEVR/blob/5176cbd1554bb703479af8451b1452d51e7dff28/docs/research/unity-engine-access.md)

## Small falsifiable probes

These are future probes, not results. Use an unchanged desktop fixture build with frozen editor/packages/backend/graphics API and hashes. Build variants can deliberately retain or strip facilities, but injected success must happen after the original player build.

| Probe | Required observation and rejection condition |
| --- | --- |
| Mixed fixture capture | Include overlay/camera/world canvases, masks, text, alpha checker, multiple displays, two Toolkit panels, IMGUI and custom texture UI. Compare original desktop with each captured layer. Missing layers, duplicate UI, altered order or bad alpha/color rejects that route for the tested cell. |
| Coordinate grid | Hit center/corners and clipped controls on flat and curved panels, with crop/scale/Y variants. Log ray UV, capture pixel, original UI position, picked object and rendered cursor pixel. Any systematic mismatch rejects the mapping. |
| Stateful input | Exercise press-drag-release outside target, scroll, slider, button, navigation, submit/cancel, focus switch and text entry. Count original handlers and gameplay actions. Missing cancellation, doubled action, stuck press or mismatched focus rejects dispatch/capture behavior. Text entry remains a separate route to validate. |
| Callback invariants | Count Update/FixedUpdate, OnGUI event types, Canvas notifications and custom render callbacks. A UI capture must not repeat gameplay updates or duplicate callbacks with gameplay side effects. No extra OnGUI invocations are assumed safe. |
| Lifecycle restoration | Destroy/recreate panels during pause/menu/scene transitions; fail capture mid-frame; disable while dragging. Compare desktop layout, cameras/targets, mappings, modules/actions, cursor/focus and live resources with baseline. Any lingering override or accidental release-click rejects cleanup. |
| Actual games | Inspect Firewatch and Outer Wilds first to identify their UI family. Run menu/HUD/pause and scene-transition checkpoints within the accepted 3 to 5 minute physical gate. If neither covers a family, add an explicitly identified non-VR title or fixture; do not claim IMGUI/Toolkit support by association. |
| Retention/backend variants | Probe exact callable capture/event APIs on Mono and IL2CPP and controlled stripped builds. Record a missing API separately from a bad capture result. Retry an alternate mechanism before declaring that particular cell unsupported. |

The Steam Frame testbench's planned streamed-launch extension can correlate host layer capture/input diagnostics with headset screenshots and run IDs. Headset pixels alone do not reveal the selected widget, its event count or restored desktop state, so host evidence remains necessary. This research passes no physical or functional gate.

## What is resolved

The factual prerequisite is sufficient for the UI decision: uGUI modes, Toolkit panels and IMGUI require distinct capture/input contracts; Toolkit has an explicit version-qualified texture/mapping API; stock event machinery already handles richer interaction than clicks; and retention, restoration and callback side effects must be probed in each shipped player. Capture fidelity policy, menu/HUD placement, pointer delivery progression and fallback acceptance remain the human's decision. Universal native interception and recovery of absent UI facilities remain prototype questions, not proven solutions or impossibility claims.
