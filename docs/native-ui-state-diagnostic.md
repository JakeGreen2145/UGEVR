# Native UI state observations

`Diagnostics.CaptureNativeUiState` defaults to `false`. Setting it to `true` enables a diagnostic for requested image captures. It requires `CaptureImages=true`, overlay capture, and a `capture-request` already present before the eye pair begins. Disabled and unrequested pairs perform no native UI sampling. When those three settings are enabled, a request arriving during a pair stays on disk until a following successful pair admits it before borrowing. That pair consumes the request and writes images with native observations. A failed pair retains the pending request. Ordinary image-only captures keep accepting late requests; overlay-disabled image captures do not wait for native admission and have no overlay native snapshot.

The adapter admits CanvasRenderer references from the selected overlay roots' existing hierarchy inventories. It performs no extra scene or canvas inventory query. `Diagnostics.NativeUiRendererLimit` defaults to 1024; the explicit experimental range is 1024..8192. The setting is validated only when native UI diagnostics and image capture are enabled. Admission permits at most that many renderer references and eight times the setting in encountered occurrences that can perform identity queries, at most 65536. An explicit 4096 limit admits up to 4096 renderers and 32768 occurrences. Later occurrences are counted as drops, including possible duplicates. Names are bounded to 64 UTF-16 units. The renderer set is fixed before borrowing; newly created renderers are not admitted during callbacks. The JSON records both effective limits.

Existing capture and restoration-failure JSON include `overlayCapture.nativeUiState` for admitted pairs. Each renderer records public `cull`, `hasRectClipping` and local `GetAlpha()` values before borrowing, after each returned or failed game-eye render, after each separate UI-eye render, and after the outer camera/UI restoration. Unused UI passes remain explicitly uncaptured. Sampling after a render does not prove that those were the values during every GPU draw.

Inherited alpha is a separate optional observation. Shipped-artifact inspection found public `GetInheritedAlpha()` in Outer Wilds' Unity 2019.4.39f1 UIModule, but not Firewatch's Unity 2017.4.40f1 UIModule. Reflection admits only the exact CanvasRenderer-declared public instance method with no arguments, a float return, no generic parameters and no virtual dispatch. Missing or unsupported shapes report `inheritedAlphaAvailable=false`; local alpha is never labeled inherited alpha. Both versions expose the common culling/clipping/local-alpha getters, and both game-reference builds compile this diagnostic.

Each phase also records the current `RenderTexture.active` identity, `Camera.current` identity and target, and the selected game camera's target. These are engine property observations, not a complete Direct3D render-state snapshot. Nulls and getter errors remain distinct through per-phase error counts.

The summary reports admitted/dropped/duplicate occurrences, admission errors, getter attempts, query errors, nonfinite values, destroyed samples and captured phases. Nonfinite numeric values serialize as null with an explicit counter. Renderer IDs and context values are private, current-run evidence. Serialization performs no new engine queries.

The base diagnostic never assigns cull, clipping or alpha values. It requests no extra rendering, layout rebuild, material query or preferred-size calculation. It neither relaxes existing guards nor asserts that native UI state was restored. Native batching, clip rectangles, materials, shader globals and queued GPU commands remain outside its observations. A before-borrow sample taken during an already active VR session cannot prove the original desktop state or exclude state left by earlier pairs. Diagnostic getter overhead can change frame timing, especially with an increased bound, so these captures do not qualify performance.

## Borrowed graphic geometry and asset identities

`Diagnostics.CaptureUiGraphicDetails=false` is a separate opt-in. It additionally requires `CaptureImages`, `CaptureNativeUiState`, overlay capture and the same pre-pair capture request. Enabling native UI state alone retains its original getter scope. The additional data appears under `overlayCapture.nativeUiState.graphicDetails`, linked to existing renderer/root IDs and the same six phase indices. Existing capture metadata supplies the owned-session, rendered-pair, game-frame and runtime-generation association; these samples do not identify a particular GPU draw or exact submit event.

The detail inventory uses only renderers already admitted by the native UI diagnostic. It admits the first 64 per selected root, at most 256 total, in recorded root order. Root IDs, per-root admissions/drops and global drops are explicit. It adds one local component query per admitted renderer when the inspected uGUI assembly is available, retaining at most 16 components for the Graphic association. Excess component inventories remain unavailable rather than guessing a partial match. It performs no new scene or subtree scan. References are fixed before borrowing; callbacks cannot introduce new entries.

Each sampled row records the renderer GameObject's activity, cached child rectangle and Graphic IDs, actual parent/root rectangle IDs, child/root rectangles, anchors, pivot, size, anchored position, world corners and corners converted to the selected root's local coordinates. It reads renderer color, actual material/pop counts and the first four slots of each, plus pop-instruction state. Material rows contain material, shader and material-main-texture IDs/names. Canonical Image rows additionally contain public color and sprite/texture identity; canonical Text rows contain public color. Strings are limited to 256 UTF-16 units. The existing native samples supply cull, clip flags and alpha; existing desktop-flush diagnostics remain separate. Phase five follows the existing outer restoration and final rebuild, without an additional flush or render pass.

Only the two inspected shipped `UnityEngine.UI` MVIDs admit Graphic getters: `77113f89-90f5-421e-9612-be5b86cac085` and `576a1661-0fc3-4a1a-9fd2-ae2d01246769`. Their exact canonical Image/Text types inherit `Graphic.color` without an override; both that getter and `Image.sprite` only read cached fields in the inspected CIL. Custom subclasses and other builds remain getter-unavailable. The diagnostic never invokes `Graphic.canvas`, `rectTransform`, `canvasRenderer`, `material`, `materialForRendering`, `mainTexture`, a default-material factory, a mesh generator or a game getter. Built-in `GameObject.transform` supplies the rectangle without populating the Graphic's lazy caches. `CanvasRenderer.GetMaterial`/`GetPopMaterial` return existing slots; `Renderer.material` is never used. Material main texture is an asset-property read, not a readback of the renderer's hidden `SetTexture` override. Null material textures, custom shaders, stencil state and missing Graphic observations must not be treated as an absent texture or an attributed pixel producer.

Each phase retains at most 524288 characters of detail sample JSON. Once the next sampled row would exceed that cap, it and all later rows are marked omitted for that phase; subsequent rows receive no reads. The row that discovers the cap can have attempted reads without a retained sample. Header counts, per-phase omissions, read-operation attempts, query errors, nonfinite values, slot omissions and string truncations remain explicit. Read-operation counts cover the explicitly wrapped reads, not every internal Unity call. Nonfinite numbers are null with counters. Destroyed entries remain marked. Serialization performs no engine reads and repeated phases do not resample. A truncated or omitted inventory cannot prove that a suspected graphic was absent.

Geometry and asset identity can support comparison of a visible rectangle with the borrowed panel. They cannot establish which graphic generated a black strip, circle or scene mesh. Samples occur after existing render calls, not during every draw. They do not cover shader globals, texture contents, all material properties, generated meshes, scene skinned meshes, native clip rectangles or inherited softness. No cull, clip, alpha, material, Animator, hierarchy or matrix setter is added, and the default remains off.

Unity documents [cull as whether emitted geometry is ignored](https://docs.unity3d.com/2019.4/Documentation/ScriptReference/CanvasRenderer-cull.html). Its [CanvasRenderer API](https://docs.unity3d.com/2019.4/Documentation/ScriptReference/CanvasRenderer.html) lists the clipping flag and alpha methods. The [uGUI clipping implementation](https://raw.githubusercontent.com/Unity-Technologies/uGUI/2017.4/UnityEngine.UI/UI/Core/MaskableGraphic.cs) changes culling state and invokes culling callbacks. These sources justify observing the fields; unchanged observations alone cannot establish that the desktop UI was drawn correctly.
