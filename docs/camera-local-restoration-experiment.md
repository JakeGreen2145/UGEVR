# Camera local restoration experiment

`[Rendering] CameraTransformRestoration = world` remains the default. It keeps the existing world position/rotation save and restoration order, with no optional transform/context queries or local writes. `local-with-world-fallback` retains the earlier explicitly selected experiment. `guarded-local` is a separate additive candidate with a stricter conflict policy, described below. Neither alternative is promoted to default or general compatibility on the focused captures alone.

Completed Outer observations on the preceding parent-pose package show three actual position predicates failing after camera disposal by approximately 55, 82 and 48 micrometres. Parent identity, recorded matrices/poses/scales remained identical at all eight sampled stages. The rotation terms were skipped. A post-cancel control passed. These observations support testing a local alternative; they do not prove native roundtrip precision or continuous parent stability.

The alternative saves raw local position/rotation and camera localScale, camera/transform/parent references and finite parent world/local pose, local/lossy scale and both matrices at CameraState admission. It measures the effective raw Unity world eye position/rotation immediately after each injector transform write and before Render. It does not use normalized domain eye rotations as evidence.

After overlay teardown, before any camera restoration setter, the alternative samples a bounded context. It requires the same live camera/transform/parent objects, a live parent at admission, exact component-equal finite parent context and unchanged camera localScale. The current pose must pass the existing Unity position-first/quaternion equality predicates against the last effective raw eye sample. Missing samples, nonfinite data, query failures and changed context refuse local restoration. Sampled equality cannot rule out intervening ABA changes or establish atomic access.

If eligible, CameraState writes saved local position followed by saved local rotation instead of its world setters. It then completes the existing remaining camera restoration fields and samples the post-restoration context/actual raw world/local result. The post sample is after those remaining setters, not an atomic read immediately after localRotation. A post-context change is reported without a second correction. No parent, scale or hierarchy setter is used.

If eligibility fails, the selected mode deliberately uses the existing world restoration. Its name openly includes that fallback. It does not claim to preserve foreign transform changes; the current world restoration's ownership limitations remain. Setter exceptions keep the existing partial-cleanup/idempotence behavior. Private evidence records an incomplete return and a bounded exception category. The experiment does not introduce cleanup retries or a general per-property ownership policy.

With `Diagnostics.CaptureImages=true` and `CaptureCameraRestorationPoseDetails=true` in a controller-owned session, fresh admitted capture requests produce private evidence. The alternative labels `changes_restoration_policy: true`, selected/applied space, refusal/fallback reason, post-context result, raw owned operands and predicate results. Its actual helper samples occupy `camera_state_saved`, `before_camera_state_dispose` and `after_camera_state_dispose`. They retain raw saved local values and independently sampled pre/post values. Default captures retain their existing eight-stage sequence. The alternative replaces `after_canvas_flush` with `before_camera_state_dispose`, declares `stage_layout`, and keeps at most eight records, eight stages and 32KiB per file. Whole records exceeding the byte cap are refused without truncation or overwrite. Other stages are sequential diagnostic reads, not the same snapshot as the helper operands.

The original anchor-based aggregate uses the unchanged Unity predicates and short circuit after image capture. Local success, unchanged sampled parent context and a returned restore are not game-consumption or fidelity claims. The actual aggregate can still fail. A physical baseline/alternative comparison should retain the same game mode and head conditions, inspect every guard and post-context result, and verify the unchanged actual position predicate. Compare saved versus restored local values as well as world values. A parent or callback conflict is a refusal/result to inspect, not a reason to widen tolerances.

Controlled checks exercise actual CameraState calls through a boundary whose world setters deliberately introduce a known bias while local setters do not. They validate selection, query/write order, default absence of optional reads, exact parent guards, raw quaternion behavior, explicit fallback, no mid-restore correction, render exceptions, partial setters and bounded private output. That fixture is policy evidence, not a model or proof of Unity native conversion.

## Guarded local candidate

Explicit `guarded-local` saves the same canonical local pose, finite context and identity at admission. A root camera is supported when its parent is an actual null reference. A destroyed parent is not treated as a root. Nonfinite or unavailable saved context rejects admission before borrowing. At restoration, context must still match and the effective last-eye world and local positions and quaternions must be component-equal to their saved raw readback. Local ownership is checked independently because a tiny foreign local change can round to unchanged world floats at a large parent offset. This ownership check uses no position epsilon, quaternion normalization or sign equivalence. Component equality is not a native bitwise or signed-zero instrumentation claim.

An eligible scope restores local position then local rotation. It checks the sampled post-context, exact saved local components and the unchanged Unity world position/rotation predicates. A parent/transform replacement, destroyed object, foreign pose, query failure, partial setter or post-context change makes scope disposal throw before the injector can submit the pair. Eligibility refusal writes no pose at all. There is no world fallback or second correction in this mode. Each remaining borrowed camera field receives one independent restoration attempt, so a failed pose or target setter does not skip viewport, mask, background or matrix cleanup. Destroyed cameras cannot be restored and explicitly refuse completion. Repeated disposal does not overwrite later game state or retry a partial failure.

Private captures identify `selected_restoration_mode: guarded-local`, a `guarded_local_restoration` result, actual local/preserved-pose selection, refusal and failure category, post-context and returned status. The existing eight-stage/32 KiB bounds and actual aggregate predicate remain. Sampled checks do not exclude ABA or asynchronous native changes between getters/setters. This candidate requires a new same-package original-game trial, including the previously failing roasting state and a foreign-context refusal, before any support or default-policy claim. The three prior successful captures exercised `local-with-world-fallback`, not this new mode.
