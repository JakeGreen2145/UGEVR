# Injector session protocol, version 1

The production session controller starts a game with `UGEVR_SESSION_ID` set to a GUID and `UGEVR_SESSION_DIRECTORY` set to an absolute per-session directory. The Mono plugin has no dependency on Frame Testbench. Without either environment variable it operates standalone; an incomplete or invalid session configuration prevents initialization and logs the reason.

The plugin atomically replaces `injector-status.yaml` at least once per second while Unity's `Update` callback runs, including when VR rendering is disabled. Paused or blocked engine callbacks can make the status stale. The controller treats a file older than ten seconds as stale. A heartbeat does not prove GPU progress or a physical headset connection.

Transient Windows replacement contention receives up to three retries after 5, 10 and 20 milliseconds. Only atomic replacement is retried. Exhaustion preserves the previous complete status file, cleans the temporary file and reports an error for the next heartbeat; it does not crash the engine callback or overwrite the destination in place. A subsequent successful publication clears its transient status-write error. Readers should allow read, write and delete sharing.

```yaml
schema_version: 1
run_id: '00000000-0000-0000-0000-000000000001'
process_id: 1234
unity_version: '2017.4.40f1'
engine_ready: true
runtime: 'openvr'
runtime_ready: true
rendering_active: false
submitted_pairs: 42
acknowledged_revision: 3
last_error: ''
```

`engine_ready` requires at least two recurring `Update` callbacks. `runtime_ready` means OpenVR initialized and the compositor and targets are available. `rendering_active` requires a recent acknowledged, successful paired submission while enabled. `submitted_pairs` is the bridge's count of successful paired submissions, not evidence of game images on a headset. The controller validates both `run_id` and `process_id` against its owned target identity. Timestamp freshness is distinct from all readiness fields.

The external producer atomically replaces `command.txt` with flat UEVR-style `key=value` lines. It serializes revisions within one run. The file is at most 4096 bytes; unknown or duplicated keys, malformed values and a mismatched run are rejected with `last_error` and no acknowledgment.

```ini
run_id=00000000-0000-0000-0000-000000000001
revision=4
enabled=true
recenter=yaw
```

`revision` is a positive signed 64-bit integer. `enabled` is exactly `true` or `false`. Optional `recenter` supports `true` for full tracked position and yaw, `position`, `yaw`, `height`, and `false` for no operation. Recenter needs enabled rendering and a valid tracked head sample. A disabled command with recenter remains unacknowledged with an error. Stale revisions have no side effects. A received command is acknowledged only after application, not after parsing. Disable waits for the native render callback to release its owned texture references; recenter waits for a valid sample.

The initial origin captures head position and yaw once. A game-camera replacement never recalibrates tracking. `UnitsPerMeter`, configured in the plugin's `Tracking` section, scales both head translation and eye separation. It defaults to one and must be finite and positive. Game position and horizontal yaw provide the default anchor. `RetainGamePitchAndRoll` explicitly permits game tilt; tracked head tilt and full eye-to-head orientation always remain live. Composition uses world-space position/rotation, so nonuniform parent scale does not stretch eye separation.

Each eye pair borrows one selected camera after the normal game frame. Both eyes use the same anchor and tracked sample. A restoration scope restores transform, target, projection, view, viewport, occlusion, background and clear flags even when rendering throws. This does not prove arbitrary game render callbacks have no gameplay side effects. Those effects and per-eye temporal history need runtime probes. `Application.runInBackground` is borrowed while VR is enabled and restored on disable/failure when the value still matches the injector's assignment.

The S1 adapter rejects a non-x64 or non-D3D11 process before passing any texture pointer to the native bridge. It retains the game's near/far clip and occlusion setting by default. Invalid clip distances fail with an actionable error. `Rendering.DisableOcclusionCulling=false` is an explicit, logged fidelity remedy when enabled; it affects eye rendering and restores the game value afterward. Runtime correctness still needs frustum-edge and culling probes.

OpenVR raw projection bounds keep their original signs. Its `top` output describes the -Y edge and `bottom` the +Y edge, as documented in [Valve's projection contract](https://github.com/ValveSoftware/openvr/blob/master/docs/Driver_API_Documentation.md). Unity receives `Frustum(left*near,right*near,top*near,bottom*near,near,far)`. Negating and swapping those Y bounds incorrectly reflected Steam Frame's vertical asymmetry; symmetric simulated-headset tests did not expose it. Controlled checks compare both eyes against independently observed runtime projection matrices. Physical alignment still requires the corrected distribution to be exercised.

Matrix restoration preserves automatic Unity projection/view updates when the original values match the engine's `ResetProjectionMatrix` / `ResetWorldToCameraMatrix` results. Distinct custom matrices are restored explicitly. Unity's public API does not expose its internal override flags, so a custom matrix exactly equal to an automatic matrix cannot be distinguished. This probe occurs without rendering. It avoids freezing an ordinary camera's future view or FOV by restoring every matrix as a setter override. Exact custom/default behavior, including temporal-jitter callbacks, remains a runtime validation case.

Native event 0 waits for poses, event 1 submits, event 2 optionally captures a compositor image, and event 3 clears the bridge's references. The managed producer associates waits/submissions with a monotonically increasing generation and frame ID. It waits for explicit completed identities before consuming poses or reusing the state for another pair. Callback posting is not completion. The initial conservative producer spans engine frames rather than blocking the engine thread on an undocumented texture-query synchronization assumption; prediction and timing need measured runtime validation.

Pose errors report both native bridge status and the OpenVR wait result. Bridge rejection for a removed device or invalid texture can happen before `WaitGetPoses`; its not-ready wait value must not be described as an OpenVR wait failure.

An acknowledged native `BridgeInvalidPose` result with a successful wait is a bounded tracking interruption. The producer requests fresh pose frames in the same runtime/resource generation for up to five seconds from the first invalid sample. It does not render, submit or apply recenter while the HMD is invalid. A valid native wait permits reading the managed pose; valid managed flags and matrix must also be confirmed before the window resets. A managed invalid sample after a valid native wait keeps the original deadline. All other bridge statuses and nonzero wait errors retain the failure path.

When the deadline expires, VR pauses and queues the existing reference drain. Heartbeats remain live with `rendering_active: false` and an actionable tracking diagnostic. Wake or reconnect the headset, then explicitly retry with F8 or a new controller `enabled=true` revision. A pending old recenter command cannot silently reopen the window, and recenter is never acknowledged from an invalid sample. A late valid callback cannot resume the paused window. Recovery does not reinitialize OpenVR, unload the DLL or change texture/GPU ownership; an unresolved native callback or drain still requires its existing lifetime precautions.

Disable stops new pairs and restores owned game/background state. Eye targets remain alive until process teardown because the reference-drain API does not establish GPU idle. The plugin does not call `OpenVR.Shutdown` or unload its DLL while queued callbacks can use runtime/resources. If drain takes longer than five seconds, status reports the unresolved operation and recommends a game restart. This initial lifetime policy supports disable/reenable, not safe DLL unloading or complete runtime-restart recovery.

Image collection is opt-in through `Diagnostics.CaptureImages=false` by default. When explicitly enabled, a `UnityVR-evidence/capture-request` file requests the next eye-pair images and compositor capture. No automatic frame-120 capture or image directory is created by default. Existing JSON pose records remain the prototype evidence format. Capture failures restore `RenderTexture.active` and destroy the temporary image, then fail the VR pipeline with an actionable log.

Each requested capture also attempts `capture-diagnostics-N.json`, with at most 64 enabled cameras and 64 active root canvases. It includes orthographic status, depth, masks, clear flags, target, viewport, stereo properties and camera component type names, plus known engine-owned canvas render modes and world cameras. It records OpenVR raw tangents and each matrix assigned before the game's render callbacks. This snapshot changes no game settings and does not claim what a later game callback renders. A diagnostic-query failure is logged separately and does not stop VR. Camera/canvas counts expose truncation; `FindObjectsOfType` still queries the engine's complete active canvas inventory and this explicit diagnostic can have a measurable cost.

Read-only engine context also records `Application.isFocused`, `Application.runInBackground` and the current screen dimensions. It does not inspect or override game-specific focus/input consumers. UI root snapshots record known standard `CanvasScaler` and `GraphicRaycaster` properties before borrowing, during each eye and after restoration. Custom component getters are not invoked.

`UI.CaptureOverlayCanvases=false` is the default. Enabling it activates an experimental adapter for active root `ScreenSpaceOverlay` uGUI canvases on the selected camera's display. It temporarily converts only those roots to one common `WorldSpace` panel per root before the first eye. Both eyes view the same geometry. `OverlayPlaneDistanceMeters=2` scales with world units and is bounded strictly inside the game's near/far clips. `OverlayPanelWidthMeters=1.8` explicitly controls physical width while preserving each root's original desktop logical dimensions, aspect and pivot. At two meters this is about 48 degrees wide; game FOV and asymmetric eye frustums do not lay out the UI. Existing screen-camera UI, world-space UI and unknown custom UI keep their modes. The default common panel uses the game camera; the separate after-effects option below creates an owned UI camera. Neither path replays `OnGUI`. Positive uniform parent scales are supported without reparenting; nonuniform/negative parent scales require an explicit adapter.

Selected canvas properties and up to 8192 descendant RectTransforms are snapshotted before conversion and restored in an exception-safe scope. Every property restoration is attempted even when another setter fails. Destroyed objects and values that fail restoration are recorded; restoration conflicts stop the VR pipeline with an error. Canvas callbacks and layout updates are explicitly invoked once to prepare the common panel and after restoring overlay mode. This can run game canvas callbacks; it is an experimental fidelity remedy requiring runtime validation, not proof of side-effect-free UI capture. State snapshots cannot undo arbitrary gameplay changes made by callbacks. Converted world panels can be depth-tested against game geometry; readable menus, clipping and overlay occlusion need physical validation.

`UI.IncludeOverlayLayers=false` keeps the original camera mask. If selected overlay renderer layers are excluded, the diagnostics report them. Explicitly enabling this separate option includes only the selected canvases' renderer layer bits for the borrowed eye render, then restores the original mask. Other scene geometry on those layers can become visible, so no automatic layer remedy is applied.

Capture diagnostics include original/applied masks, effective plane distance, selected roots, per-eye applied canvas geometry and restoration conflicts. Camera-mode conversion does not by itself prove a common physical UI plane, correct binocular convergence, readable text through the runtime crop or preserved pointer mapping. The controlled fixture checks selection and restoration code; host eye and physical headset captures plus original game input are required before accepting the adapter.

With diagnostic capture explicitly enabled, a restoration conflict writes a bounded `ui-restoration-failure-G-F.json` even if no successful capture request has completed. At most eight are written per plugin run. They are failure records with `pairSubmitted=false`, not successful image/frame evidence. Rectangle mismatches identify the name, current-run instance ID, field, expected and observed numeric values, finiteness, maximum absolute delta and acceptance tolerance.

The first physical failure recorded `SpecialFeaturesMask.anchoredPosition3D.y` changing from `2.3` to `2.29999924` after the adapter assigned both coupled position fields. Restoration now treats `anchoredPosition3D` as the canonical layout value and does not overwrite it through `localPosition`. Anchors, pivot, size, scale and anchored position retain strict checks. Derived `localPosition` permits at most four float ULPs per component, recording any accepted roundoff separately from restoration conflicts. A controlled coupled-field fixture reproduces the observed subtraction loss and checks canonical restoration. This bound does not excuse layout or callback changes beyond floating-point representation.

A later physical run recorded one-ULP normalization of the save spinner's quaternion. Quaternion restoration therefore validates finite, near-unit inputs with squared norm within `0.000002` of one, aligns equivalent quaternion signs and permits at most four float ULPs per component. Accepted normalization is counted and retains raw expected/observed values and unit checks. Zero, nonfinite, nonunit or materially different orientations fail; other rectangle fields are not relaxed by this rule.

`UI.OverlayAfterImageEffects=false` is a separate experimental opt-in. When enabled with overlay capture, the adapter selects an unnamed layer unused by loaded scene objects, including inactive objects. It temporarily moves only selected canvas roots, nested canvases and canvas renderer objects to that layer. The borrowed game eye camera excludes that private bit while retaining its effects and all other masks. A separate disabled camera, with no copied game components or image effects, then renders the UI into the same eye texture using forward rendering and a depth-only clear. This preserves the original overlay's order after depth of field/bloom instead of disabling those game effects. Private-layer and pipeline behavior require physical validation.

The isolated pass checks layer occupancy again immediately before borrowing and checks for unowned renderers after the game render. No unused layer, an oversized query or a new unowned renderer fails explicitly. A selected overlay hierarchy containing an initially active independently rooted canvas requires an explicit adapter before any mutation. Scope cleanup restores owned object layers and masks; a newer conflicting layer change is preserved and reported. Other manual cameras or global render callbacks can still observe temporary state, so source-level isolation alone does not prove broader gameplay safety. The disabled UI camera releases its borrowed target after every pass and on failure. After the surrounding game camera has been restored, the adapter rebuilds desktop canvas geometry and verifies the saved rectangle state again.

Concrete runtime guards identified an inactive world-space confirmation popup in Firewatch and an inactive world-space blocker in Outer Wilds beneath selected overlay roots. Up to 64 such independent inactive canvases are now protected boundaries. Their canvas mode, camera, scale, sorting, display and other settings are snapshotted and verified without assignments; their activity is never toggled. Their descendant rectangles and UI object layers already belong to the borrowed ancestor hierarchy and restore through that scope. An enabled world renderer on an active descendant object rejects this path, even if the canvas component is disabled. Renderer inventories are bounded to 8192 entries.

Protected boundaries must remain inactive with unchanged settings and no active world renderers before borrowing, after each game render, after each UI render and after desktop restoration. A violation prevents submission, restores owned transforms/layers and preserves the game's newer activity or settings. Diagnostics record `protectedInactiveCanvases` and successful `inactiveCanvasValidationPasses`. Arbitrary callback changes that activate and deactivate a canvas wholly between those checks cannot be proven absent by this adapter. Initially active world-space or camera-space descendants remain unsupported; this change introduces no conversion for them. Physical launch, pause-menu and focus-transition tests remain required.

`appliedEyes` and `afterRenderEyes` report root geometry and standard UI context on both sides of the manual render. A changed snapshot is reported explicitly. These engine property queries do not independently prove what the GPU drew or establish headset readability.

A loading-scene camera can itself be a descendant RectTransform of a selected overlay. In that case the outer camera scope writes its world position after the UI scope restored its local values. A controlled float roundtrip reproduces the recorded loss of a `0.0000305175781` local Y offset when the world Y is near 1080. After the outer camera scope, the adapter restores only that already-owned camera rectangle's saved local rotation and canonical anchored position before rebuilding desktop geometry. It records `selectedCameraRectRestorations`; all rectangle comparisons remain unchanged. Mismatch records include `verificationPhase` to distinguish scope restoration from the final camera/layout rebuild. A later layout callback changing even that small anchored offset still fails strict verification.

The standalone `diagnostics/VRProbe` also reports both eyes' raw tangents and the equivalent unit-near Unity frustum bounds without needing injector redeployment. It is a separate runtime observer. A cropped OpenVR headset screenshot cannot alone establish a vertical stereo defect; compare the actual applied eye poses, raw frustums and projected corresponding rays first.

Run `dotnet run --project tests/ManagedBoundary/ManagedBoundary.csproj -c Release` for known transform, scale/recenter, canted-eye and restoration checks, plus a separate producer process that writes commands through the external file boundary. The camera fixture verifies the restoration code's assignments but does not simulate Unity's native camera lifetime. Clean managed builds against both game assembly sets do not establish same-binary runtime compatibility; the physical gameplay gate remains outstanding.
