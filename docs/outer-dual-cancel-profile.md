# Outer dual-hand cancel profile

`outer-1.4.1-dual-hand-a-west-b-east-sticks-v1` is a separate compiled InputSystem profile. Explicitly set `Input.AllowOpenVrGamepadDiagnostic = true`, select it with `Input.DiagnosticProfile`, select a current-device conflict policy and use `Input.DiagnosticNeutralReads = 3`. Activation defaults off and profile defaults to `none`. A controller session is required; simultaneous Rewired and E experiments refuse. Existing profiles retain their old readers, interfaces and one-button state semantics.

The source is the inspected Outer application view of `Oculus Quest2 (Left Controller)` and `Oculus Quest2 (Right Controller)`, with successful axis0..4 declarations `[2,3,3,0,0]` on both hands. These names describe the compatibility view of the exercised streamed transport, not physical hardware identity or support for every Quest controller. A completed passive 171-record window observed right pressed mask 2 in five in-game records, matching eight independent Windows reads and ten headset B-action samples. Other records and both endpoints were neutral; all raw axes stayed zero. Touched also reported 2 but never authorizes pressed input.

| Received source | Owned public Gamepad output |
| --- | --- |
| right pressed 128, established A route | West, GPAD bit 7 |
| right pressed 2, observed B route | East, GPAD bit 5 |
| left raw axis0 X/Y | leftStick through configured radial deadzone |
| right raw axis0 X/Y | rightStick through configured radial deadzone |

OpenVR source mask 2 and InputSystem output mask 32 are different contracts. No B enum, touched bit, modern action origin or alternate mask substitutes for pressed 2. No South, left A, PrimaryAction or trigger mapping is added. Unrequested controls stay zero on the separate owned device; physical keyboard/gamepad state is never written.

Existing game/InputSystem assembly MVID guards, honest owned GPAD layout, device/layout identity and conditional Current restoration remain unchanged. Added public pins are `Gamepad.get_buttonEast` `0x06000448` and GamepadButton.East field `0x040004d3`, value 5. South 6/West 7 retain their pins; old backends do not resolve or read East. Complete GPAD events independently combine West/East and both sticks. East-only is nonneutral and cannot bypass a Current conflict.

The SDK-only reader shares passive paired observation queries without creating an observer, evidence files or Rewired backend. Initial distinct role/indices and Controller classes are required. Each hand has independent bounded pre/post serial/model reads, successful joint connected/valid/finite standing pose/state and successful full metadata. Semantic metadata follows the joint poll. All raw axes must be finite and within [-1,1]. Fresh final serial/model, all five metadata and role/index/class checks follow both polls, then final role contexts are checked again. Unknown, missing or changed results refuse publication. Raw serials never enter normal logs. The same already-open CVRSystem is used, with no SDK initialization or manifest. Sequential checks do not establish an atomic snapshot or hardware sample age.

Admission requires three consecutive neutral pairs from the same identities, model/signature, roles/indices and runtime generation. Both complete source pressed masks must be zero, including B and any unrequested held button. Both radial stick mappings must be zero. Faults, held input, focus loss and pre-window pause reset admission. Admission packet regression resets it; unsigned wrap and equal packets remain permitted. Those guards, finite monotonic time and the 5..300-second window remain enforced after admission. Loss ends this one window without a one-hand fallback or automatic recreation.

Owned public readback includes East, West and both sticks after ordinary InputSystem processing. `appliedStateSamples` acknowledges all desired channels, not original action consumption. Ordinary pause/disable permits at most two seconds for processed full-neutral release. `neutralObserved` requires East/West released and both sticks neutral. Failed or stuck East keeps it false. Release/removal have at most two attempts. Lifecycle teardown, ownership takeover and immediate faults may remove the device before neutral processing; logs retain that distinction. Removal failure remains `cleanup_unconfirmed`. External Current and changed layouts follow existing preservation rules.

The default asset binds `Menu/cancel` to `<Gamepad>/{Back}`. The normal shipped loader substitutes Back with `<Gamepad>/buttonEast`: `InputCommandManager.InitializePlatformActionOverrides` `0x06000f20` and `SanitizeActionForPlatform` `0x06000f2f`. `InputLibrary.get_cancel` `0x06000cad` selects command 104. This adapter neither invokes those game methods nor changes bindings, unknown players or game state. Saved rebinding, user/device filters and legal menu/roast context still apply. B transport, owned processed East, original Cancel response and the accepted gameplay gate are separate evidence requirements. Original Cancel consumption remains unvalidated for this profile.
