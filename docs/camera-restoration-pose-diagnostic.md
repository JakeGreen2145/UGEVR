# Camera restoration pose diagnostic

`Diagnostics.CaptureCameraRestorationPoseDetails = true` explicitly enables private passive pose evidence. It defaults to false and requires `CaptureImages` and a controller session. With this flag enabled, a capture request must arrive before the eye pair. A request arriving during the pair remains available for the next pair, so image capture requires a pose record admitted for the same pair. The flag leaves native UI sampling controlled by its existing separate option.

Before a pair, the injector moves the existing `capture-request` to one uniquely named private claim. After a successful pair it consumes only that claim, and only while the same ownership token and pose record remain admitted. A new request at the original path remains separate. An interrupted pair returns its claim to the original path when that path is absent. If a newer request already occupies it, the injector retains at most one owned claim and retries it before admitting the newer request. Teardown returns the claim where possible and preserves both files on collision. A later owner never adopts an old claim. Request contents are not parsed.

Each launch permits at most eight records named `camera-restoration-pose-N.yaml` in its controller-owned `UnityVR-evidence` directory. Existing files count toward that bound. Each record has at most eight stages and a 32 KiB UTF-8 limit. Serialization completes before file creation, and publication uses a fresh temporary file and non-overwriting rename. Output collisions preserve the existing file. Path ancestors must have no reparse points. These checks assume the private directory remains stable; they do not make filesystem operations atomic against another writer.

Once the record budget is exhausted, additional requests remain pending and image capture defers for the rest of that launch. A new launch supplies a fresh budget subject to existing output files. Claim, deletion or publication failures remain sanitized diagnostic errors. An image operation or record publication can still fail after consumption, so a consumed request alone does not prove that both images and the pose file were saved. Interrupted records retain false completion fields and null observations for stages that did not run.

The stages follow the existing engine path:

1. `anchor_before_scope`, before overlay scope construction. World position and rotation use the exact earlier base anchor used by the existing aggregate comparison; local pose and parent are fresh sequential reads at this boundary.
2. `camera_state_saved`, using the exact world position and rotation saved by `CameraState`, before its matrix inspection. Local pose and parent identity are separate sequential public reads at that point.
3. `after_left_render` and `after_right_render`, following each eye's game/UI render and existing UI observations.
4. `after_camera_state_dispose`, after all normal camera restoration writes return and before the outer canvas rebuild/flush. Failed construction or disposal has no such stage.
5. `after_canvas_flush`, after the existing optional restored-geometry rebuild returns. With no overlay scope this is a boundary observation with no canvas flush.
6. `after_current_context`, after the existing current-camera scope disposal returns.
7. `after_eye_captures`, in a finally block around image capture. Separate attempt and normal-return fields distinguish a failed first image from two normally returned captures.

Each stage records public camera/transform/parent instance identities, exact stored world/local positions and quaternion components, per-array finiteness flags, and a bounded query-error category. Finite numbers use round-trip formatting; NaN and infinity are quoted and flagged. Values are never normalized or substituted. A missing or destroyed camera remains unavailable. A getter failure preserves any already-returned fields and leaves later fields unavailable. Parent absence is distinct from failed parent inspection. No object name, game getter or game callback is queried.

Each admitted stage also reads the camera transform's local and lossy scale, local-to-world matrix and world-to-local matrix. For the parent reference observed at that boundary, it reads world/local position and rotation, local/lossy scale and both matrices. Matrices contain exactly sixteen elements in Unity's single-index order, from zero through fifteen. Each array has a finiteness flag. `parent_query_error` distinguishes a failed parent getter from a verified absent parent and preserves completed camera fields. These are fresh sequential getters, not an atomic hierarchy snapshot. An unchanged parent instance ID does not prove that its pose stayed fixed.

`existing_game_camera_restored` copies the unchanged aggregate after eye capture: Unity's existing world-position and quaternion equality against the earlier base anchor. Its tolerance and comparison phase are unchanged. An interrupted path retains null if that comparison did not run. Exact component differences in this record do not override that result, identify a cause, or authorize a restoration fix. Native frame ID, runtime generation and planned rendered-pair ordinal link the record to the existing `capture-N.json` and eye filenames. A failed pair may never reach that ordinal or queue submission; the record does not claim GPU completion. Unity API reads and stage observations are sequential, not an atomic pose snapshot.

`actual_comparison` retains the operands and term results from that same aggregate expression. It reads world position once and compares it to the original anchor with Unity's existing equality. Only a successful position term permits the existing world-rotation getter and quaternion equality. A false position term leaves the rotation operand, rotation result and signed dot unavailable. An original getter exception still propagates; the record retains completed operands and a sanitized error. With the diagnostic absent, the injector runs the original aggregate expression directly.

After predicate evaluation, diagnostic arithmetic computes squared position distance with Unity's float `Vector3.sqrMagnitude` and raw signed quaternion dot with `Quaternion.Dot`, using only those already sampled structs. It adds no transform query, normalization or comparison tolerance. These float results are serialized as their exact promoted double values with finiteness flags. They describe the admitted comparison operands, unlike the separate sequential pose-stage observations or domain-normalized rotations in other capture files. They do not establish setter precision, parent motion or a callback as the cause of a mismatch.

The eight-record, eight-stage and 32 KiB bounds are unchanged. Extended serialization still completes before publication. An oversized or failed record publishes no partial file and reports its sanitized failure category. Matrix and parent getters can perturb diagnostic timing, so this option remains explicitly opt-in for requested pairs.

Normal logs report only the bounded attempt count and sanitized diagnostic failure category. Pose and instance identities remain in private evidence. Use an ignored private controller session directory and sanitize any public export. Disabled diagnostics create no observer and add no transform/identity reads, evidence files or per-pair logs. This code makes no additional camera, parent, matrix or game-state writes. It cannot interrupt a blocked Unity API or image-capture operation, and a process exit before publication may leave no record.

With the pose option disabled, ordinary image requests retain their existing late-arrival behavior. Native UI requests retain their existing pre-pair admission rule. Request claims add no scene scan or native UI getter, and no admission helper exists on the disabled path.
