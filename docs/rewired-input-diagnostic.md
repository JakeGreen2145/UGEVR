# Owned Rewired input prototype

This default-off prototype maps one right controller to Firewatch's normal stick-look and trigger actions. It uses public Rewired definitions, maps, assignments and input-update callbacks. It invokes no private game method, changes no interaction requirement, and installs no native hook or global device driver. It has not been validated in a running game.

Select the profile explicitly in a controller-managed launch:

```ini
[Diagnostics]
CaptureImages = true
AllowEngineInputExperiment = false

[Input]
AllowOpenVrGamepadDiagnostic = false
AllowRewiredInputDiagnostic = true
RewiredDiagnosticProfile = firewatch-2017-rewired-right-stick-trigger-v1
RewiredConflictPolicy = refuse
RewiredDurationSeconds = 15
RewiredStickDeadzone = 0.2
CaptureRewiredActionReadback = false
```

## Passive channel observation

`Input.CaptureRewiredSourceDetails = true` opts into a separate private SDK observer. It requires a controller-owned session and runs independently of `AllowRewiredInputDiagnostic`, its profile and `CaptureImages`. It creates no Rewired or InputSystem device, supplies no input and does not resolve ambiguous Trigger metadata. Keep input activation off when collecting channels without testing a binding.

After the injector has started, atomically place a new UTF-8 file named `rewired-source-request` in that session's `UnityVR-evidence` directory:

```ini
run_id=<this controller session's GUID>
request_id=<a new GUID for this window>
```

Only those two fields are accepted, within 256 bytes. A file already present when the observer starts is stale. A new request nonce after startup is required. Claimed requests remain as `rewired-source-request.claimed-1` through `-3`; they prevent nonce replay and preserve the three-window budget across component recreation. Invalid claimed requests also consume a slot. No existing claim or result is overwritten. Requests are accepted only in focused, enabled, rendering VR on the Unity owner thread. An unconsumed request can wait for those conditions.

Each accepted window lasts 15 elapsed seconds, samples at most once per 50ms and contains at most 300 records. It never catches up with several reads in one Update. Disabled or unfocused ticks perform no SDK read and add no record; the deadline continues. Component disable, teardown, opt-out, a regressing clock or a bounded record failure ends the active window. A stalled Unity thread cannot execute its deadline or publish evidence until it runs again. Cancelled or incomplete windows are reported with their reason and actual record count.

`rewired-source-window-N.yaml` is a private YAML stream with a header, one document per sample, and an ending summary. Records include monotonic ticks, UTC time, runtime generation, queried and post-poll right index/class/role, public joint state/pose result, connected/valid/finite flags, all twelve matrix entries, packet number, full unsigned pressed/touched masks, all five raw axis XY pairs, and each axis property's raw return/type/error/exception. The reused reader also records one pre-state axis0 metadata query. Bounded serial/model API observations include their raw values, result/errors, required byte counts and builder lengths/capacities. Normal logs contain status, count and reason only. Treat the file as private device evidence and sanitize identities before publishing it.

An SDK false return sets `raw_outputs_valid: false`; returned raw fields remain visible and are not treated as a valid neutral sample. Exceptions leave unavailable output fields null and retain their API category. Failed property queries retain raw returns separately from accepted type values. Nonfinite matrix/axis values are quoted explicitly. These observations establish neither input admission nor game consumption.

The observer holds records in bounded memory, with a 16384-byte record limit and 5MiB window limit. It serializes each complete record before adding it, then publishes the complete stream through a fresh temporary file and non-overwriting rename. Failed serialization never inserts a partial sample. An output collision preserves the prior file and reports `output_unconfirmed`. Existing path ancestors and request/output directories are checked for reparse points. These checks require the controller-owned directory to remain stable; they do not claim atomic protection against a concurrent process replacing filesystem paths.

The profile requires the inspected Assembly-CSharp MVID `4e377d15-4996-4da3-9447-797d50034429`, SHA256 `145b56aebe921c0fdc660a4e64008272e09a283332146958ce2f356c7490522a`, and Rewired_Core MVID `159fb15d-62c3-4977-b0f0-ed64736f91be`, SHA256 `15508ee97bbf97731f20be14e40b36d208507ad475b97c896866d39c13aef87b`. It checks already loaded assembly identities and their file hashes, then exact public mutator shapes/tokens. It loads no target assembly. An unready, missing or ambiguous active input manager refuses creation. Other game versions require another evidenced profile.

Admission requires focused active VR, valid connected right-controller state and pose, bounded serial identity, unchanged right role, declared joystick axis0, and exactly one declared Trigger axis among axes1..4. All five axis properties must succeed. Missing, ambiguous or unknown metadata refuses input before a Rewired device is created. Raw axis values alone do not establish their meaning; a Frame transport fallback requires separate observed channel evidence and explicit selection. A fresh stick whose radial magnitude is within the configured deadzone and an exactly zero trigger start the one allowed window. The same radial condition produces zero stick output, including diagonal and nondefault deadzone cases. Duration is bounded to 5..300 seconds; radial stick deadzone is .1...8. Trigger values remain analog in 0..1 for ordinary game threshold logic.

The reader checks the initial right role and controller class, polls joint state and pose, then queries metadata and serial in the same OpenVR context. A failed poll, disconnected or invalid pose, or nonfinite pose matrix stops before property reads. All existing metadata, serial, post-poll role and analog guards still precede publication. A controlled function-table fixture exposes properties only after the joint poll and verifies that persistent unknown metadata and two declared Trigger axes still refuse input. This ordering does not establish physical Rewired compatibility or select a trigger when metadata is ambiguous.

## Explicit observed finger-trigger source profile

`firewatch-2017-rewired-right-stick-observed-trigger-axis1-v1` selects an independently observed finger-trigger channel when the application-view metadata declares both axis1 and axis2 as Trigger. It accepts only the exact successful model `Oculus Quest2 (Right Controller)` and successful axis-type signature `[2,3,3,0,0]`. Axis0 must therefore be Joystick, axes1 and2 Trigger, and axes3 and4 None. No UnknownProperty fallback is accepted. Axis1 X supplies the analog finger trigger; axis0 X/Y supply ordinary stick look. Other raw axes and buttons are not forwarded. The original unique-trigger profile and parameterless reader retain their ambiguity refusal.

The reader captures the actual initial RightHand index, Controller class and role, then attempts bounded serial and model queries before the joint state/pose read. It checks context again, then requires a connected, valid, finite pose and successful state. A valid role-scoped joint query still runs when the initial properties are unknown or the model differs, so it can expose application-view properties for a later read. That first unsuccessful bracket cannot publish input or proceed to metadata admission. Invalid initial context and thrown queries never receive this bootstrap exception.

Once the initial serial and exact model both succeed, all five metadata properties must match the signature twice, with an intervening context check. Independent fresh serial/model calls after those joint and metadata queries must equal their initial values, followed by another index/class/role check. Mapped stick components must be finite within [-1,1] and the mapped trigger finite within [0,1]; the reader refuses out-of-range values instead of clamping or normalizing them. These sequential public checks do not form an atomic snapshot or establish the age of controller state. A property exposed only after joint polling requires a later read with both successful sides before admission; the passive observer need not prime it.

This addition provides `PublicOwnedRewiredInput.ObservedTriggerProfile`, `SupportsProfile` and `OpenVrRewiredRightReader.Read(system, profile)`. It uses the existing bounded owned Rewired backend and admission/lifecycle policy; the existing factory and parameterless reader remain available. Injector validates the selected profile with `SupportsProfile`, stores that selection and passes it to the reader in ordinary Update. A neutral mapped stick and exactly zero mapped trigger admit one window. Later serial, selected trigger axis, generation or packet faults, unavailable reader output and normal session/lifecycle faults use the existing release and cleanup path. Model or signature changes become unavailable output before the policy can feed another state.

The source profile is based on the root operator's cleaned private `firewatch-rewired-source-layer20` window on 2026-10-14. The in-game SDK recorded 267 samples with successful joint state, Controller/RightHand context and query/post index agreement; model reads and axis-type signature above succeeded. During one requested trigger-only 0.60 pulse, eight received held samples had axis1 X `0.5984252095`, the other nine raw axis components zero, and pressed bit33. A separate Windows observer also placed the finger-trigger pulse on channel1. Another window recorded nine axis0 X/Y samples. These observations justify this explicit channel selection, not a full-range calibration, timing guarantee, another application/model, or original Firewatch action consumption. This route maps analog axis1 X, not bit33.

The passive collector did not provide a fresh initial serial: its initial serial was null, and its post-serial fields shared one observation object. Serial stability across records is not a bracket around a read. The active profile therefore requires its own fresh initial and post serial/model calls and does not accept passive output as an Available input sample. Physical source admission and original look/Use still require runtime validation.

The public backend refuses any existing custom definition/device or physical Rewired joystick. It requires the existing category0/custom-layout0 and exact action names/IDs. It creates one definition with three axes, one definition map, one runtime custom controller, and one map/assignment on the system player. The map connects axes0/1 to `LookXAxis_Stick`31 and `LookYAxis_Stick`32, and axis2 to `DialogDownButton`36. The inspected default game context routes the latter through `DialogSelectionDownOrUse` and its normal dialog/radio/target checks. A is not mapped to Use. Locomotion and other controller buttons are outside this prototype.

## Owned map activation and public action readback

The retained InputManager assets declare the System player's custom map category0/layout0 disabled by default. Public `AddController`0600225b follows the custom assignment helper0600227b and initial-map loader06002472. Its helper06002473 reads the setting's `startEnabled`06002162 and passes enable-mode2 for false. The map-set implementation06001fe1 then calls public `ControllerMap.set_enabled`06001e2c with false. A normally loaded map can therefore exist while its actions remain unavailable. The fallback four-argument `LoadMap`06002386 passes mode0; it does not explicitly enable a new map. A configured map enabler can change this later, but the retained System-player rule sets are empty. Static initialization does not prove a particular live map's state.

The explicit owned profile now activates only its admitted fresh runtime map. Before the setter, the backend requires its exact CustomControllerMap type, source editor-map ID, controller/category/layout identity, expected three action/channel mappings, intact definition and runtime channels, and sole owned assignment/map. The new controller must already be enabled. A disabled controller refuses admission; the injector never enables a device to bypass that refusal.

The pinned public nonvirtual map setter's complete body is `_enabled = value; ret`. The adapter invokes it only if the owned map is disabled, requires normal return and true public getter readback, and compares full ownership before and after while excluding only that map's root XML `enabled` attribute. XML remains bounded, with DTD/external resolution prohibited; serialized and public enable values must agree. All other XML, object references, entries and configuration remain in the proof. A final enabled/context/content check precedes the new ordinary full snapshot and callback subscription. A normal return with false readback refuses input. A throw or content disagreement keeps the prior expected snapshot; changed resources are preserved by existing cleanup rules. No global defaults, enabler rules, other map or physical device state is changed. Sequential public checks do not claim atomic protection against a concurrent writer.

`Input.CaptureRewiredActionReadback = true` separately enables fixed public observations during the admitted input window, at most once per elapsed second with no catch-up. The five-second minimum window yields at most five samples; the 300-second maximum yields at most300. Complete retains the last sample and performs no further read. `REWIRED_READBACK` logs sample count and elapsed sample age, the owned map/device enabled values, owned raw axes0/1/2, System-player raw actions31/32/36 and whether the global last-active controller reference equals the owned device. It logs no controller name, tag or hardware ID. Default-off performs no additional action/activity queries.

The exact public readback methods are `ControllerMap.get_enabled`06001e2b, `Controller.get_enabled`06000724, `ControllerWithAxes.GetAxisRaw(int)`06000839, `Player.GetAxisRaw(int)`060021f9 and global `ControllerHelper.GetLastActiveController()`06002847. The last helper also has a generic zero-argument overload; bounded metadata selection admits only the pinned nongeneric Controller-returning shape. Readbacks do not invoke private game accessors. Failed and nonfinite fields remain unavailable. `readbackFailedFields` bits0..8 correspond to map enabled, device enabled, owned axes0/1/2, System actions31/32/36 and last-active agreement. `readbackNonfiniteFields` identifies the failed numeric fields whose return was NaN or infinity.

Setter returns, processed owned-axis values, System action aggregation and original game consumption are separate observations. `SetAxisValue` writes the controller's input-source buffer; ordinary engine processing exposes axes later. The global activity selector includes custom devices and compares their last element-change time, independently of map enable or action output. A map can be disabled while its device is active. An unchanged last sample with increasing age is not fresh action evidence. Southpaw remapping, game input-mode/context gates and original interaction requirements still apply after successful public action aggregation; logs retain `gameConsumption=unknown`.

The source supplies values to the public `InputSourceUpdateEvent`. Each desired state expires after 500ms without refresh, or at the window deadline. A callback checks focus, monotonic time and ownership independently of the injector Update. Source loss, identity/trigger-axis change, packet regression, VR generation change, disable, focus loss or lifecycle teardown stops the window. Expiry checks and neutral release run when Unity calls Update or the Rewired event; a stalled engine cannot acknowledge them. A returned public setter is not engine action readback or game consumption.

The backend also monitors delivery on each eligible injector policy tick. It requires public `ReInput.isReady`, the admitted manager's active/enabled state and `userData`, the original global controller/player helpers, system-player controller/map helpers and exact owned device reference. It allows 500ms for the first ordinary input callback, then requires another callback within each 500ms interval. Callback timing and source expiry use the same monotonic `Stopwatch` clock. An additional full ownership inspection runs at most once per 100ms, so a missing callback cannot indefinitely suppress inspection. Public runtime replacement, readiness loss, stale callback delivery, clock faults and changed content retain a sanitized terminating diagnostic and end the one allowed window. The adapter does not re-subscribe or recreate a device after that window ends.

Every value write also checks the admitted public runtime context. A missing callback with an intact context still permits bounded neutral release and owned-resource removal. A replaced or inactive context permanently blocks writes into the retired controller and preserves its definitions rather than reporting confirmed release. Component teardown performs that check even if no later policy tick ran. Sequential public checks cannot prove an atomic runtime snapshot or observe a reset and reconstruction that occurs entirely between checks. Callback freshness detects missing delivery only after its bounded deadline.

The pinned Core's `ReInput.Reset` calls `InputManager_Base.ResetAll`, teardown, and a helper that clears the same event container used by public `InputSourceUpdateEvent` add/remove. Ordinary `OnSceneLoaded` dispatches a separate scene event and does not clear that container itself. This static evidence motivates delivery/context checks; it does not establish that a particular saved-game transition called Reset.

Image capture synchronously performs `ReadPixels`, `Apply`, PNG encoding and file writes on Unity's main thread. A sufficiently long capture or other main-thread stall can exceed the existing source-refresh deadline. Its duration is not measured by this adapter. A controlled elapsed-clock fixture confirms that an ordinary callback after a 500ms refresh gap neutralizes intact channels, retains `source_expired_or_clock_invalid` and ends the window on the next policy tick. It does not establish the cause or duration of any physical stall. Capture and input validation should use separate windows when measuring original game response.

The pinned nonvirtual `AddCustomController` CIL constructs a fresh concrete definition and inserts it with `List.Add`; its constructor, ID factory and name helpers contain no application callback or overridable dispatch. Only a normally returned call followed by the sole new definition is admitted. A thrown void creation leaves an unknown new definition untouched. Runtime creation passes a unique public controller `tag`; both returned devices and recovery after null/throw require that exact tag, source ID and sole global reference. A foreign device using the same definition ID is preserved. A newly returned definition map must be empty; preexisting entries are preserved without clearing them.

The pinned public nonvirtual `UserData.CreateCustomControllerMap`, token `0x0600153c`, unconditionally returns false at IL140..141 after constructing and adding its map. That Boolean is not a success flag in this shipped build. Its complete call chain constructs `ControllerMap_Editor` at `0x06002006`, assigns the new ID/category/layout/custom definition ID and empty hardware GUID, then performs `List.Add`. The ID helper `0x0600158a` only returns and increments `customControllerMapIdCounter`; the map constructor initializes an empty action-element list. Neither path contains an application callback or virtual factory dispatch. Static CIL here establishes the pinned managed code, not unmodified runtime JIT code or an atomic guarantee against concurrent writers.

The adapter admits map creation only after a normal public call return, no prior map for its admitted definition, exactly one post-call map with that definition/category0/layout0 and exact editor-map type, an unchanged definition/channel snapshot, and an empty entry list. It then records the full map snapshot before adding its own three entries. A false result with no addition remains unavailable. Duplicate or mismatched maps, added initial entries, changed definitions, null entry collections and thrown calls after partial mutation refuse input. An unproved map outcome keeps the previous ownership snapshot and follows the existing preservation rules rather than clearing unknown content or adopting a plausible map from a thrown call. No counters are reset and no second window is attempted.

Cleanup detaches only the exact owned delegate and releases only the created controller's axes. Fresh checks compare definition, axis/identifier, editor-map entry, runtime-map and assignment references, public configuration values and runtime-map XML. The shipped nested axis has two inherited public fields and eleven own public fields; all are covered, including calibration, sensitivity, curve reference/values and hardware-info reference/values. Identifiers include their public ID, names, element and compound types. Curves include wrap modes and at most64 keys with time/value/tangents/tangent mode, plus weights when exposed. Shipped 2017 and2019 Unity metadata confirm these public getters. Float fingerprints use round-trip formatting. A keys array is allocated by Unity before its returned length is checked; the preceding length check bounds intended inspection, not native allocation under concurrent mutation. Other bounds are controller/player/definition collections64, complete player map inspection1024, definition children16, and each serialized field/map65536 characters. The initial active-manager query is bounded to16 returned objects for inspection; Unity allocates its query result first.

Every value write, including expiry/error/teardown zeroes, requires the admitted definition-channel snapshot and runtime-channel snapshot to remain intact. The runtime proof checks the device tag/source ID/runtime ID, its three axis and identifier references/order/IDs, ordinary index lookup, polling deadzones, enabled state and calibration references/public values/curves/XML. Empty serialization is a failure, because the shipped serializer can return empty on error. A changed tag, definition channel, runtime axis or calibration prevents any further value write and reports `neutral_release_unconfirmed`; input release is not claimed in that case. Changed editor/runtime maps can still be preserved after zeroing only the intact original channels.

Replaced IDs, changed observed mappings/calibration, new observed axes/entries/maps, duplicate or additional player assignments, new custom/physical devices, incomplete collections and failed getters prevent destructive cleanup. An unrelated new definition can remain while the exact owned definition is deleted using a fresh identity lookup. Definition deletion also removes its definition maps, so a second proof runs after runtime device destruction. Observed public definition/map additions during destruction are preserved. Uncertain creation outcomes or incomplete cleanup report `cleanup_unconfirmed` and may leave detached owned objects until process exit; neutralization remains unconfirmed when channel identity/configuration has changed. The prototype never resets ID counters, restores a whole collection snapshot, or claims a complete observation of private engine caches or callback state. In particular, custom axis/button callbacks have public setters but no public readback. Complete static token scans of the pinned Core CIL found no callers of those setters, and the pinned game and shipped Windows backend have no direct member references to them. Their private fields begin null/false on the normal creation path. Arbitrary reflection, third-party code or runtime hooks installing a hidden callback remain outside this observed public ownership proof.

Logs report status/reason, creation/removal attempts, returned public update feeds, and cleanup status with `gameConsumption=unknown`. No ordinary camera motion, targeting receipt, settings persistence, gameplay progression or gate completion is inferred from these counters. Game-driven input/settings saves remain an untested persistence boundary.

Terminating creation failures also retain bounded `failureStage`, `failureCategory`, `exceptionType` and one `innerExceptionType` through cleanup and Complete. Public member/method failures name only their controlled API operation; method shape/token checks remain strict. Public preflight reports readiness and definition/custom-device/joystick counts only when the existing guard actually queried them. `not_read` distinguishes a short-circuited guard from zero. Known categories distinguish an unready manager, existing definitions/custom devices/joysticks, action-name disagreement, unavailable category/layout0, public method shape/token mismatch and a thrown public invocation. Application-defined exception types use `non_system_exception`. No exception message, full exception, returned property text, serial, device ID or owned tag enters these logs.

`AddAttempts=1`, `cleanup=not_created` and no removal attempts indicate failure before the backend set its mutation flag; they alone cannot identify which preflight operation refused. A factory failure has zero Add attempts. A failure after partial creation still follows the existing ownership proof and bounded cleanup or preservation rules, and cleanup errors cannot replace the retained terminating diagnostic. These fields neither loosen a guard nor restart the one allowed window.

The source-only checks use controlled public API fixtures and the real vendored OpenVR function-table ABI. They cover radial/trigger admission, creation/assignment/mapping/feed/cleanup, foreign same-definition devices, every selected mutable axis and identifier configuration, changed and added content, changes during destruction, ID reuse, partial failures, expiry, conflicts and axis metadata. The fixtures do not establish native Rewired execution. Static origin analysis also does not establish unmodified JIT code, concurrent application writes or native callback behavior. Both shipped Unity reference builds compile the adapter without depending on proprietary Rewired assemblies at build time.

[Rewired's custom-controller documentation](https://guavaman.com/projects/rewired/docs/CustomControllers.html) describes explicit assignment/maps and update-event delivery. [Its player documentation](https://guavaman.com/projects/rewired/docs/Players.html) describes ordinary action aggregation. Shipped metadata and CIL establish the selected API and game-consumer profile; the current documentation alone does not prove compatibility with the older shipped build.
