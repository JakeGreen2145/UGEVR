# Owned Rewired input prototype

This default-off prototype offers explicit right-hand look/trigger profiles and a separate five-channel profile for both sticks and the observed right finger trigger. It uses public Rewired definitions, maps, assignments and input-update callbacks. It invokes no private game method, changes no interaction requirement, and installs no native hook or global device driver. The right-hand route has private public-axis and original-camera response evidence. The new five-channel consumer route remains physically unvalidated.

Select the profile explicitly in a controller-managed launch:

```ini
[Diagnostics]
CaptureImages = true
AllowEngineInputExperiment = false

[Input]
AllowOpenVrGamepadDiagnostic = false
AllowRewiredInputDiagnostic = true
RewiredDiagnosticProfile = firewatch-2017-rewired-right-stick-trigger-v1
RewiredConflictPolicy = refuse
RewiredDurationSeconds = 15
RewiredStickDeadzone = 0.2
CaptureRewiredActionReadback = false
```

## Passive channel observation

`Input.CaptureRewiredSourceDetails = true` opts into a separate private SDK observer. It requires a controller-owned session and runs independently of `AllowRewiredInputDiagnostic`, its profile and `CaptureImages`. It creates no Rewired or InputSystem device, supplies no input and does not resolve ambiguous Trigger metadata. Keep input activation off when collecting channels without testing a binding.

After the injector has started, atomically place a new UTF-8 file named `rewired-source-request` in that session's `UnityVR-evidence` directory:

```ini
run_id=<this controller session's GUID>
request_id=<a new GUID for this window>
```

Only those two fields are accepted, within 256 bytes. A file already present when the observer starts is stale. A new request nonce after startup is required. Claimed requests remain as `rewired-source-request.claimed-1` through `-3`; they prevent nonce replay and preserve the three-window budget across component recreation. Invalid claimed requests also consume a slot. No existing claim or result is overwritten. Requests are accepted only in focused, enabled, rendering VR on the Unity owner thread. An unconsumed request can wait for those conditions.

Each accepted window lasts 15 elapsed seconds, samples at most once per 50ms and contains at most 300 records. It never catches up with several reads in one Update. Disabled or unfocused ticks perform no SDK read and add no record; the deadline continues. Component disable, teardown, opt-out, a regressing clock or a bounded record failure ends the active window. A stalled Unity thread cannot execute its deadline or publish evidence until it runs again. Cancelled or incomplete windows are reported with their reason and actual record count.

`rewired-source-window-N.yaml` is a private YAML stream with a header, one document per sample, and an ending summary. Records include monotonic ticks, UTC time, runtime generation, queried and post-poll right index/class/role, public joint state/pose result, connected/valid/finite flags, all twelve matrix entries, packet number, full unsigned pressed/touched masks, all five raw axis XY pairs, and each axis property's raw return/type/error/exception. The reused reader also records one pre-state axis0 metadata query. Bounded serial/model API observations include their raw values, result/errors, required byte counts and builder lengths/capacities. Normal logs contain status, count and reason only. Treat the file as private device evidence and sanitize identities before publishing it.

An SDK false return sets `raw_outputs_valid: false`; returned raw fields remain visible and are not treated as a valid neutral sample. Exceptions leave unavailable output fields null and retain their API category. Failed property queries retain raw returns separately from accepted type values. Nonfinite matrix/axis values are quoted explicitly. These observations establish neither input admission nor game consumption.

The observer holds records in bounded memory, with a 16384-byte record limit and 5MiB window limit. It serializes each complete record before adding it, then publishes the complete stream through a fresh temporary file and non-overwriting rename. Failed serialization never inserts a partial sample. An output collision preserves the prior file and reports `output_unconfirmed`. Existing path ancestors and request/output directories are checked for reparse points. These checks require the controller-owned directory to remain stable; they do not claim atomic protection against a concurrent process replacing filesystem paths.

## Passive paired source observation

`Input.CaptureRewiredPairSourceDetails = true` opts into a separate two-hand public SDK evidence stream. It defaults to false and requires the controller-owned session. It works with Rewired and InputSystem activation disabled and does not require images. It creates no SDK client, manifest, game input device or callback, and supplies no input. The 256-byte request parser, stale-at-startup refusal, claim/readback comparison, nonce replay protection, owner-thread checks, pause/focus behavior and non-overwriting publication are the existing shared window controls. Pair claims/results have their own `rewired-pair-source-request.claimed-N` and `rewired-pair-source-window-N.yaml` namespace and three-window launch budget. They do not consume or overwrite the separate right-only stream.

Each paired window uses 15 elapsed seconds, at most 300 complete paired records and at most 20 Hz, with no catch-up. Each sample uses the same already-open CVRSystem on Unity's owner thread. It records independent initial left/right role indices, class and actual role at each queried index, then fresh serial/model observations before each hand's standing-origin joint state/pose query. All twelve pose matrix values, packet, unsigned pressed/touched masks, ten raw axis components and all five axis-type raw returns/success-or-error results are recorded per hand. Fresh post-context and post-serial/model reads follow that hand's query. After both hands, a final complete left/right role-index/class/role recheck records class/role at the original queried indices. No before/after string observation object is shared between phases or hands.

The private schema 2 record labels successful raw outputs separately from SDK false and exception outcomes. A false return preserves the output storage but sets `raw_outputs_valid: false`; it never invents neutral controller input. A thrown API leaves unavailable values null. Axis-property raw returns and errors remain separate from successful type values; a thrown query has no reported API error code. Unknown successful enum integers remain raw. Nonfinite matrix/axis entries are quoted with explicit finiteness flags. Bounded text observations retain required bytes, builder length/capacity, raw truncation and accepted-result verdict. Failed text calls do not report the error variable's initial Success value as a returned SDK result.

Pair context consistency requires all initial/post/final observations and checks both role/class/index agreement and distinct indices. Pair identity consistency compares independent successful before/after serial/model values and distinct serials. Unknown observations keep those summaries null; known differences become false. These are passive consistency summaries, never an input-admission result, model whitelist, semantic-axis selection, atomic snapshot or hardware-age guarantee. Final context does not add another serial/model bracket after both hands. Initial property failure still permits the joint poll and later raw observations, but no missing value is repaired or aliased into the earlier phase.

The conservative serialization fixture measures 53,438 payload bytes with maximally escaped bounded property/context/exception strings, large numeric storage and the longest SDK error names. The paired cap is therefore 65,536 bytes including the fixed sample envelope; the right-only cap stays 16,384. Each paired window retains the shared 5 MiB total bound. Large valid records can end the window before 300 samples with `record_bound_exceeded`; they are not truncated to fit. UTF-8 encoding/serialization or byte-limit failure never appends a partial record. API strings use the existing 257-byte calls and at most 256-character private raw storage; overlong returned builder values are explicitly marked truncated/unaccepted. Exception-type observations are bounded to 128 characters, without exception messages.

Normal `REWIRED_PAIR_SOURCE_OBSERVATION` logs contain status, window/sample counts, fixed reason and error type only. Raw serial/model values, axes and poses stay in private evidence. Use an ignored private session directory and sanitize records before any public export. A stalled Unity thread or synchronous SDK call cannot be interrupted by this observer; deadline handling and final file publication occur when the owner thread runs again. Component disable or teardown ends the active window. This addition establishes no left-hand profile, movement binding, original game consumption or physical compatibility result.

Changed editor/runtime maps can still be preserved after zeroing only the intact original channels.

Replaced IDs, changed observed mappings/calibration, new observed axes/entries/maps, duplicate or additional player assignments, new custom/physical devices, incomplete collections and failed getters prevent destructive cleanup. An unrelated new definition can remain while the exact owned definition is deleted using a fresh identity lookup. Definition deletion also removes its definition maps, so a second proof runs after runtime device destruction. Observed public definition/map additions during destruction are preserved. Uncertain creation outcomes or incomplete cleanup report `cleanup_unconfirmed` and may leave detached owned objects until process exit; neutralization remains unconfirmed when channel identity/configuration has changed. The prototype never resets ID counters, restores a whole collection snapshot, or claims a complete observation of private engine caches or callback state. In particular, custom axis/button callbacks have public setters but no public readback. Complete static token scans of the pinned Core CIL found no callers of those setters, and the pinned game and shipped Windows backend have no direct member references to them. Their private fields begin null/false on the normal creation path. Arbitrary reflection, third-party code or runtime hooks installing a hidden callback remain outside this observed public ownership proof.

Logs report status/reason, creation/removal attempts, returned public update feeds, and cleanup status with `gameConsumption=unknown`. No ordinary camera motion, targeting receipt, settings persistence, gameplay progression or gate completion is inferred from these counters. Game-driven input/settings saves remain an untested persistence boundary.

Terminating creation failures also retain bounded `failureStage`, `failureCategory`, `exceptionType` and one `innerExceptionType` through cleanup and Complete. Public member/method failures name only their controlled API operation; method shape/token checks remain strict. Public preflight reports readiness and definition/custom-device/joystick counts only when the existing guard actually queried them. `not_read` distinguishes a short-circuited guard from zero. Known categories distinguish an unready manager, existing definitions/custom devices/joysticks, action-name disagreement, unavailable category/layout0, public method shape/token mismatch and a thrown public invocation. Application-defined exception types use `non_system_exception`. No exception message, full exception, returned property text, serial, device ID or owned tag enters these logs.

`AddAttempts=1`, `cleanup=not_created` and no removal attempts indicate failure before the backend set its mutation flag; they alone cannot identify which preflight operation refused. A factory failure has zero Add attempts. A failure after partial creation still follows the existing ownership proof and bounded cleanup or preservation rules, and cleanup errors cannot replace the retained terminating diagnostic. These fields neither loosen a guard nor restart the one allowed window.

The source-only checks use controlled public API fixtures and the real vendored OpenVR function-table ABI. They cover radial/trigger admission, creation/assignment/mapping/feed/cleanup, foreign same-definition devices, every selected mutable axis and identifier configuration, changed and added content, changes during destruction, ID reuse, partial failures, expiry, conflicts and axis metadata. The fixtures do not establish native Rewired execution. Static origin analysis also does not establish unmodified JIT code, concurrent application writes or native callback behavior. Both shipped Unity reference builds compile the adapter without depending on proprietary Rewired assemblies at build time.

[Rewired's custom-controller documentation](https://guavaman.com/projects/rewired/docs/CustomControllers.html) describes explicit assignment/maps and update-event delivery. [Its player documentation](https://guavaman.com/projects/rewired/docs/Players.html) describes ordinary action aggregation. Shipped metadata and CIL establish the selected API and game-consumer profile; the current documentation alone does not prove compatibility with the older shipped build.
